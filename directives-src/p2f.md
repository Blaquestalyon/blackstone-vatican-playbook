### WBS: P2.F.1.1
:: SUMMARY
Identify the six target gatekeepers/consultants and understand each one's manager-research process. Know exactly who you are trying to get onto and how they evaluate managers.
:: DIRECTIVE
Gatekeepers control access to large pools of Catholic and institutional capital. Getting on their approved lists is the Phase 2 objective, so start by understanding each one precisely.

**Actions**
1. Confirm the six target gatekeepers/consultants and, for each, document how their manager-research and approval process actually works (research-driven rating, buy list, model portfolios, etc.).
2. Capture each one's investment focus, whether they cover values-screened/Catholic strategies, and how a manager typically enters their pipeline.
3. Note the decision cadence and any published minimums so later eligibility screening (P2.F.3) has real inputs.

**Deliverable:** a profile of each of the six gatekeepers and its research process.

**Done when:** all six are profiled with a clear picture of how each selects managers.

### WBS: P2.F.1.2
:: SUMMARY
Map each gatekeeper's key contacts, submission portals, and timelines.
:: DIRECTIVE
Turn each gatekeeper profile into an actionable route in.

**Actions**
1. For each gatekeeper, identify the specific manager-research contacts and the correct submission channel (portal, database, direct email, RFP).
2. Record submission windows, database refresh cycles, and any deadlines that affect timing.
3. Build a single contact-and-channel map across all six.

**Deliverable:** a contact, portal, and timeline map for all six gatekeepers.

**Done when:** you know who to reach, how to submit, and when, for each gatekeeper.

### WBS: P2.F.1.3
:: SUMMARY
Re-verify the current officeholders and research analysts at each gatekeeper. Names go stale; confirm before you rely on them.
:: DIRECTIVE
People move. Reaching the wrong or former analyst wastes a first impression.

**Actions**
1. Re-verify each named contact against a primary source (the firm's own site, LinkedIn, a direct call to the firm) before any outreach.
2. Update the contact map with confirmed current officeholders and note the verification date.
3. Flag any contact you could not confirm and find the current equivalent.

**Deliverable:** a verified, current contact list.

**Done when:** every contact you intend to approach is confirmed current, dated, and sourced.

### WBS: P2.F.2.1
:: SUMMARY
Contact each of the six gatekeepers to request onboarding / RFI packets.
:: DIRECTIVE
Open the relationship and pull each one's requirements.

**Actions**
1. Reach out to each verified contact through the correct channel and request the onboarding, RFI, or manager-submission packet.
2. Introduce the fund briefly with the teaser (P1.E.1), leading with the proof stack.
3. Log each request with date and channel and set a follow-up reminder.

**Deliverable:** onboarding/RFI requests sent to all six.

**Done when:** every gatekeeper has been contacted and a packet requested.

### WBS: P2.F.2.2
:: SUMMARY
Log received packets and catalog each one's requirements.
:: DIRECTIVE
Convert incoming packets into a requirements matrix you can execute against.

**Actions**
1. Log each received packet and extract its requirements: minimums, documents, formats, questionnaires, and deadlines.
2. Build a requirements matrix across all six so overlaps (reuse) and unique asks are visible.
3. Chase any gatekeeper that has not responded.

**Deliverable:** a catalogued requirements matrix for all responding gatekeepers.

**Done when:** every received packet is logged and its requirements captured in the matrix.

### WBS: P2.F.3.1
:: SUMMARY
Assess the fund against each gatekeeper's minimum eligibility criteria. A hard gate that stops dead-end submissions before they start.
:: DIRECTIVE
**HARD GATE before submissions.** This prevents wasting the wk28 submission window on gatekeepers the fund cannot yet clear.

**Actions**
1. For each gatekeeper, test the fund against its minimums: AUM, track-record length, firm tenure, strategy capacity, and any structural requirements.
2. Mark each gatekeeper pass, fail, or closable-gap, with the specific shortfall noted.
3. Summarize which targets are eligible now, which are fixable, and which are out for this cycle.

**Deliverable:** an eligibility assessment per gatekeeper with pass/fail/gap status.

**Done when:** every gatekeeper has a clear eligibility verdict feeding the go/no-go decision (P2.F.3.2).

### WBS: P2.F.3.2
:: SUMMARY
Remediate closable gaps; Kate decides go/no-go per gatekeeper. Drop ineligible targets before the submission window.
:: DIRECTIVE
**HARD GATE. Kate only — DECIDE.** She makes the call on where to spend submission effort. Chasing an ineligible gatekeeper burns credibility and time.

**Actions**
1. For gaps marked closable, execute the remediation and confirm the criterion is now met.
2. Present Kate the eligibility verdicts and remediation results.
3. Kate decides go or no-go for each gatekeeper. No-go targets are dropped or deferred; go targets advance to submission.

**Deliverable:** a go/no-go decision per gatekeeper, with remediations closed.

**Done when:** Kate has ruled on every gatekeeper and only eligible targets remain for the submission push.
